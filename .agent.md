# Cognitive Lab Agent Contract

This repository is the active research home for LEAP analysis, post-alignment behavior, and intuition-layer work. Any coding assistant working here must preserve those three maintained pillars and keep tests green across them.

## Required Read Order

Before proposing or generating code, read these in order:

1. `README.md`
2. `.github/workflows/test.yml`
3. The relevant pillar README or test file:
   - `leap_analysis/README.md`
   - `post_alignment_lab/test_post_alignment_phase2.py`
   - `intuition-layer/TESTING.md`
4. The relevant implementation file under the affected pillar

Do not treat this repository as a general scratch space.

## Repository Rules

- Keep the repository centered on the three maintained pillars:
  - `leap_analysis/`
  - `post_alignment_lab/`
  - `intuition-layer/`
- Preserve reproducible tests for each maintained pillar.
- Do not add unrelated experiments or governance assets here.
- Do not weaken existing validation into warning-only behavior.

## Required Change Protocol

When changing one of the maintained pillars, update together:

1. The relevant implementation file(s)
2. The relevant test file(s)
3. Any pillar-local README or testing note that becomes stale
4. The CI gate or workflow if the maintained validation command changes

## CI Expectations

Local validation entrypoints are:

- `python tools/ci_gate.py validate-leap-analysis`
- `python tools/ci_gate.py validate-post-alignment-lab`
- `python tools/ci_gate.py validate-intuition-layer`
- `python tools/ci_gate.py validate-governance`
- `python tools/ci_gate.py unit-tests`

All gates are binary. The only valid outcomes are `PASS` or `FAIL`.

## Preferred Agent Behavior

- Start by identifying which maintained pillar is affected.
- Make the smallest change that keeps the other two pillars untouched.
- Prefer strengthening tests over loosening assertions.
- If a request is ambiguous, choose the stricter interpretation that preserves the active research boundary.

## Forbidden Patterns

- Reintroducing split-out repositories or governance assets into this repo
- Breaking one pillar to improve another
- Adding undocumented dependencies to the CI path
- Treating local ad hoc scripts as sufficient in place of maintained tests

## Definition of Done

A change is not complete until:

- the affected pillar still has an explicit validation path
- the repository-wide tests still pass
- the CI gates remain green
